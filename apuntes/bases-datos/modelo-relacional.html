Modelo Relacional

El modelo relacional es un modelo de datos que organiza la información en tablas (o relaciones) que pueden ser relacionadas entre sí. Cada tabla tiene filas y columnas, donde cada fila representa un registro y cada columna representa un atributo del registro.

Definición del modelo relacional

El modelo relacional fue propuesto por Edgar F. Codd en 1970 y se basa en la teoría de conjuntos y la lógica de predicados. En este modelo, los datos se representan como relaciones (tablas) y las operaciones sobre los datos se realizan mediante álgebra relacional.

Características del modelo relacional

  • Tablas: Los datos se organizan en tablas.
  • Filas y columnas: Cada tabla tiene filas (registros) y columnas (atributos).
  • Claves primarias: Cada tabla tiene una clave primaria que identifica de manera única cada fila.
  • Relaciones: Las tablas pueden estar relacionadas entre sí mediante claves foráneas.
  • Valores atomicos: Valores que pueden almacenarce en una celda de la tabla.

Operaciones del modelo relacional

Las operaciones básicas del álgebra relacional incluyen:

  • Selección: Filtra filas según una condición.
  • Proyección: Selecciona columnas específicas de una tabla.
  • Unión: Combina filas de dos tablas con la misma estructura.
  • Diferencia: Devuelve las filas que están en una tabla pero no en otra.
  • Producto cartesiano: Combina todas las filas de dos tablas.
  • Join: Combina filas de dos tablas basándose en una relación.

Schema

El schema (o esquema) de una base de datos relacional define la estructura de las tablas, sus atributos y las relaciones entre ellas. Se puede representar mediante un diagrama entidad-relación (DER) o mediante un lenguaje de definición de datos (DDL).

El schema incluye:

  • Nombre de la tabla: Identificador único de la tabla.
  • Atributos: Nombre y tipo de cada columna.
  • Claves primarias: Atributo o conjunto de atributos que identifican de manera única cada fila.
  • Claves foráneas: Atributo o conjunto de atributos que establecen una relación con otra tabla.
  • Restricciones: Reglas que limitan los valores que pueden tomar los atributos (por ejemplo, NOT NULL, UNIQUE).

Ejemplo:

<nombre_tabla>(PK: int, nombre: text, ... )

Pasaje del DER al Modelo Relacional

Para convertir un diagrama entidad-relación (DER) a un modelo relacional, se siguen los siguientes pasos:

  1. Identificar las entidades y sus atributos.
  2. Crear una tabla para cada entidad.
    La tabla representa una relacion entre atributos, que conforman la entidad.
  3. Definir la clave primaria para cada tabla.
  4. Identificar las relaciones y crear tablas adicionales si es necesario.
  5. Definir las claves foráneas para establecer las relaciones entre las tablas.

Ejemplo:

Si tenemos un DER con las entidades "Cliente" y "Pedido", y una relación entre ellas, el modelo relacional podría ser:

Cliente (PK: ID_Cliente, nombre: text, ... )
Pedido (PK: ID_Pedido, fecha: date, FK: ID_Cliente)

En caso de una Generalizacion o Especializacion disyuntiva

En caso de tener una disyutinva en el DER, se agrega una columna tipo.

empleado(legajo, nombre, apellido, antiguedad, periodo_contrato, tipo)

En caso de tener una Generalizacion o Especializacion No Obligada

En caso de tener una especializacion no excluyente, no se agrega columna tipo

empleado(legajo, nombre, apellido, antiguedad, periodo_contrato) <-- sin tipo

Modelado de relaciones

El modelado de relaciones implica representar las relaciones entre entidades en el modelo relacional. Esto se hace mediante el uso de claves foráneas y la creación de tablas intermedias si es necesario.

Las relaciones pueden ser:

  • Uno a Uno (1:1): Una fila en una tabla se relaciona con una fila en otra tabla.
  • Uno a Muchos (1:N): Una fila en una tabla se relaciona con muchas filas en otra tabla.
  • Muchos a Muchos (M:N): Muchas filas en una tabla se relacionan con muchas filas en otra tabla. Se requiere una tabla intermedia para representar esta relación.

Ejemplo:

Si tenemos una relación "Cliente" y "Pedido", donde un cliente puede hacer muchos pedidos, el modelo relacional sería:

Cliente (PK: ID_Cliente, nombre: text, ... )
Pedido (PK: ID_Pedido, fecha: date, FK: ID_Cliente)

Si tuviéramos una relación "Producto" y "Pedido", donde un pedido puede contener muchos productos y un producto puede estar en muchos pedidos, necesitaríamos una tabla intermedia:

Producto (PK: ID_Producto, nombre: text, ... )
Pedido (PK: ID_Pedido, fecha: date)
Pedido_Producto (FK: ID_Pedido, FK: ID_Producto)

Primary Keys & Foreign Keys

Las claves primarias (PK) son atributos que identifican de manera única cada fila en una tabla. Las claves foráneas (FK) son atributos que establecen una relación entre dos tablas.

Las claves foráneas se utilizan para referenciar la clave primaria de otra tabla, lo que permite establecer relaciones entre las tablas.

Ejemplo:

Cliente (PK: ID_Cliente, nombre: text)
Pedido (PK: ID_Pedido, fecha: date, FK: ID_Cliente)

En este caso, la clave foránea ID_Cliente en la tabla Pedido establece una relación con la clave primaria ID_Cliente en la tabla Cliente.

PK (Primary Keys)

  • Atributo identificador
  • No se puede repetir
  • No puede ser null

FK (Foreign Keys)

  • Atributo de la PK de alguna relacion (tabla)
  • Atributo tiene que existir en alguna relacion
  • Puede ser repetida
  • Puede ser null

Modelado relacion Uno a Uno (1:1)

En una relación uno a uno, cada fila de una tabla se relaciona con una fila de otra tabla. Para modelar esta relación, se puede agregar la clave primaria de una tabla como clave foránea en la otra tabla.

Ejemplo:

Si tenemos una relación "Empleado" y "Oficina", donde cada empleado tiene una oficina asignada y cada oficina tiene un solo empleado, el modelo relacional sería:

Empleado (PK: ID_Empleado, nombre: text, FK: ID_Oficina)
Oficina (PK: ID_Oficina, ubicacion: text)

En este caso, la clave foránea ID_Oficina en la tabla Empleado establece la relación uno a uno con la tabla Oficina.

Modelado relacion Uno a Muchos (1:N)

En una relación uno a muchos, una fila de una tabla se relaciona con muchas filas de otra tabla. Para modelar esta relación, se agrega la clave primaria de la tabla "uno" como clave foránea en la tabla "muchos".

Ejemplo:

Si tenemos una relación "Cliente" y "Pedido", donde un cliente puede hacer muchos pedidos, el modelo relacional sería:

Cliente (PK: ID_Cliente, nombre: text)
Pedido (PK: ID_Pedido, fecha: date, FK: ID_Cliente)

En este caso, la clave foránea ID_Cliente en la tabla Pedido establece la relación uno a muchos con la tabla Cliente.

Modelado relacion Muchos a Muchos (M:N)

En una relación muchos a muchos, muchas filas de una tabla se relacionan con muchas filas de otra tabla. Para modelar esta relación, se crea una tabla intermedia que contiene las claves foráneas de ambas tablas.

Ejemplo:

Si tenemos una relación "Producto" y "Pedido", donde un pedido puede contener muchos productos y un producto puede estar en muchos pedidos, el modelo relacional sería:

Producto (PK: ID_Producto, nombre: text)
Pedido (PK: ID_Pedido, fecha: date)
Pedido_Producto (FK: ID_Pedido, FK: ID_Producto)

En este caso, la tabla Pedido_Producto establece la relación muchos a muchos entre Producto y Pedido.
