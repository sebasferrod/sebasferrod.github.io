Algebra Relacional

Busca formalizar la manipulacion de relaciones, en el modelo relacional. Es un fundamento para la creacion de lenguajes de consulta (SQL).

Modelo Relacional

El modelo relacional es un modelo de datos basado en la teoría de conjuntos. Se basa en la representación de datos en tablas (relaciones) y permite realizar operaciones sobre estas tablas.

  • Relaciones (tablas)
  • Records o tuplas (filas)
  • Fields o atributos (columnas)
Observaciones:
  • Los items de una fila pueden ser de distinto tipo
  • Todos los items de una columna son del mismo tipo
  • Los items de algunas columnas se pueden repetir, otros son unicos

Operaciones

  1. Selección: Permite filtrar filas de una relación según una condición.
  2. Proyección: Permite seleccionar columnas específicas de una relación.
  3. Unión: Combina dos relaciones con la misma estructura en una sola.
  4. Diferencia: Devuelve las filas que están en una relación pero no en otra.
  5. Producto cartesiano: Combina todas las filas de dos relaciones.
  6. Join: Combina filas de dos relaciones basándose en una condición de coincidencia. Es equivalente a realizar un producto cartesiano y despues una seleccion.
  7. Interseccion: Devuelve las filas que están en ambas relaciones.
  8. Diferencia: Devuelve las filas que están en una relación pero no en la otra.
  9. Division: Devuelve las filas de una relación que están relacionadas con todas las filas de otra relación.
  • Cada operacion devuelve siempre una nueva relacion
  • Las operaciones del Algebra Relacional se pueden combinar

Join

El join es una operación que combina filas de dos relaciones basándose en una condición de coincidencia. Se utiliza para combinar datos relacionados de diferentes relaciones. Se representa con el símbolo ⨝ (join). Y esta devuelve una nueva relacion con las filas que cumplen la condicion de coincidencia.

Ejemplo: Si tenemos una relación "Clientes" con las columnas "ID_Cliente", "Nombre" y "Apellido", y otra relación "Pedidos" con las columnas "ID_Pedido", "ID_Cliente" y "Fecha", el join de ambas relaciones sería:

El join es una operación muy útil para combinar datos relacionados de diferentes relaciones y se utiliza comúnmente en consultas SQL.

Ejemplo de join en SQL:

Esto selecciona el nombre de los clientes y la fecha de los pedidos donde el ID del cliente coincide en ambas tablas.

Observaciones:

  • La operación de join se puede pensar como la forma de abreviar el producto cartesiano seguido de una selección.

Natural Join

El natural join es una operación que combina filas de dos relaciones basándose en todas las columnas con el mismo nombre. Se utiliza para combinar datos relacionados de diferentes relaciones sin necesidad de especificar la condición de coincidencia. Se representa con el símbolo ⋈ (natural join). Y esta devuelve una nueva relacion con las filas que cumplen la condicion de coincidencia.

Ejemplo: Si tenemos una relación "Clientes" con las columnas "ID_Cliente", "Nombre" y "Apellido", y otra relación "Pedidos" con las columnas "ID_Cliente", "ID_Pedido" y "Fecha", el natural join de ambas relaciones sería:

Esto devolvería una nueva relación con las filas de ambas relaciones donde la columna "ID_Cliente" coincide en ambas relaciones.

El natural join es una operación muy útil para combinar datos relacionados de diferentes relaciones sin necesidad de especificar la condición de coincidencia. Se utiliza comúnmente en consultas SQL.

Ejemplo de natural join en SQL:

SELECT * FROM Clientes NATURAL JOIN Pedidos;

Esto selecciona todas las columnas de ambas tablas donde el ID del cliente coincide en ambas tablas.

Observaciones:

  • El natural join es una forma conveniente de combinar datos relacionados sin necesidad de especificar la condición de coincidencia.
  • El natural join elimina automáticamente las columnas duplicadas en el resultado.
  • El natural join se puede combinar con otras operaciones como la selección y la proyección para obtener resultados más específicos.
  • El natural join es una operación costosa en términos de rendimiento, especialmente si las relaciones originales son grandes. Por lo tanto, es importante optimizar las consultas que utilizan natural joins para mejorar el rendimiento.

¡Ojo! La diferencia, en general, no es conmutativa:

R1 - R2 != R2 - R1
