Diagrama Entidad Relación (DER)

El Diagrama Entidad Relación (DER) es una herramienta gráfica utilizada para representar la estructura de una base de datos. Permite visualizar las entidades, sus atributos y las relaciones entre ellas.

DER - Diagrama Entidad Relacion

Autores: Peter Pin-Shan Chen

Bibliografia: The Entity-Relationship Model: Toward A Unified View of Data.

Entidades

Las entidades son objetos o conceptos del mundo real que tienen una existencia independiente. La entidad es el objeto de interes. Cada entidad se representa como un rectángulo en el DER.

No se repiten entidades.

  • Ejemplo: Cliente, Producto, Pedido.

Normativa: Conjunto de entidades se representa con sustantivo singular y en minuscula.

Entidades debiles: dependen de la existencia de otra entidad. Se representan con un doble cuadrado.

Atributos

Los atributos son las propiedades o características de una entidad. Se representan como óvalos conectados a la entidad correspondiente.

  • Ejemplo: Nombre, Precio, Fecha de Pedido.

Atributos multivaluados: Se representan como un óvalo doble. El problema con los atributos multivaluados es que no se pueden representar en una tabla relacional. Se reemplazan con una entidad separada con atributos.

Atributos derivados: Se representan como un óvalo punteado.

  • Ejemplo: Edad (derivada de la fecha de nacimiento).

Relaciones

Las relaciones representan cómo las entidades están conectadas entre sí. Se representan como rombos en el DER.

Asociacion de entidades, verbo, conjunto de relaciones.

  • Ejemplo: Un Cliente realiza un Pedido.

Las relaciones pueden tener atributos.

Grado de relación: Cantidad de entidades involucradas en una relación.

  • Binaria: Relación entre dos entidades.
  • Ternaria: Relación entre tres entidades.
  • N-aria: Relación entre N entidades.
Nota: Evitar relaciones ternarias o n-arias, ya que son difíciles de implementar en una base de datos relacional. En su lugar, se recomienda descomponerlas en relaciones binarias.

Primary Key

La clave primaria es un atributo o conjunto de atributos que identifica de manera única a cada instancia de una entidad. Se representa subrayando el atributo en el DER.

  • Ejemplo: ID_Cliente, ID_Producto.

La clave primaria no puede ser nula y debe ser única para cada registro.

Nota:En realidad, se denominan identificadores unicos.

Nota: En el caso de entidades débiles, la clave primaria se compone de la clave primaria de la entidad fuerte y un atributo adicional.

Cardinalidad

La cardinalidad define la cantidad de instancias de una entidad que pueden estar asociadas con instancias de otra entidad en una relación. Se representa mediante notación en el DER.

  • Uno a Uno (1:1): Una instancia de A se relaciona con una instancia de B y viceversa.
  • Uno a Muchos (1:N): Una instancia de A se relaciona con muchas instancias de B, pero una instancia de B solo se relaciona con una instancia de A.
  • Muchos a Uno (N:1): Muchas instancias de A se relacionan con una instancia de B.
  • Muchos a Muchos (M:N): Muchas instancias de A se relacionan con muchas instancias de B.

La cardinalidad se indica mediante números o símbolos cerca de los rombos que representan las relaciones.

Se pone un 0 si puede no haber una entidad de uno de los lados de la relacion.

Nota: La cardinalidad es importante para entender cómo se relacionan las entidades y para diseñar la base de datos de manera eficiente.

Agregación

La agregacion es un concepto que permite representar una relacion entre una entidad y una relacion entre otras entidades. Se utiliza cuando una relación tiene atributos propios o cuando se desea representar una relación compleja.

Se representa como una relacion donde uno de los extremos es un cuadrado con lineas entrecortadas que contiene la relacion entre las otras entidades involucradas.

Generalización y Especialización

La generalización es el proceso de abstraer características comunes de varias entidades para crear una entidad más general. La especialización es el proceso inverso, donde se crean subentidades a partir de una entidad general.

Se representan mediante un triángulo que conecta la entidad general con las entidades especializadas.

La generalización y especialización son útiles para modelar jerarquías de entidades y para representar relaciones entre entidades de manera más clara.

Se utiliza cuando una entidad tiene subtipos o supertipos.

En caso de tratarse de una especializacion rigida, de uno u otro, el triangulo lleva una d en su interior.

En caso de tratarse de una especializacion no rigida, el triangulo lleva una o en su interior. Esto marca que ambas especializaciones pueden darse en una entidad.
